> `06d6299`. This is the agent-facing contract; the human narrative stays in
> [README.md](./README.md) and the documents it links. Every entry is grounded in the cited source,

## System Overview

`dsh-egm` is a DeepSeek Harness plugin bundle, not a standalone application. The Harness composes
the bundle patch [cordis.patch.yml](./cordis.patch.yml), which inserts two host rows —
`dsh-egm/skills-host` and `dsh-egm/reviewer-host` — and declares the read-only `egm-reviewer` agent
preset. `skills-host.js` registers the seven vendored EGM skills when the plugin activates, and
`reviewer-host.js` exposes the `egm_reviewer` tool that starts Goldfish reviewers as fresh children
in that preset. `index.js` is the package entry and re-exports the skills host.

The EGM skills, reviewer personas and shared standards/resources are vendored byte-for-byte from
[google/elephant-goldfish-model](https://github.com/google/elephant-goldfish-model) at the commit
pinned in [upstream.lock.json](./upstream.lock.json); DeepSeek Harness mechanics live only in a
`<dsh_integration>` preamble that the host prepends at registration time, never in the vendored
files ([ADAPTATIONS.md](./ADAPTATIONS.md), [ADAPTER-NOTES.md](./ADAPTER-NOTES.md)). The package
authors the integration layer, the bundle patch, the locale metadata and the upstream drift checker
in `scripts/`; the Node test suite and the recorded end-to-end run under `examples/` are
repository-only.

Human documentation that already carries the project narrative and remains the source of truth for
prose: [README.md](./README.md), [ADAPTATIONS.md](./ADAPTATIONS.md),
[ADAPTER-NOTES.md](./ADAPTER-NOTES.md) and [E2E-VERIFICATION.md](./E2E-VERIFICATION.md).

## Local Interface & Invariants

**Interface (direct source files in the repository root).**

- `index.js` — package entry; re-exports the `skills-host.js` named exports, so the package surface
  is `apply`, `inject`, `integrationPreamble`, `loadBundledSkill`, `name` and `parseSkillDocument`
  ([index.js:6](./index.js)).
- `skills-host.js` — exports `name = 'dsh-egm'`, `inject = ['skills']`,
  `parseSkillDocument(source) -> { meta, body }`, `integrationPreamble(skillName, skillDirectory)`,
  `loadBundledSkill(directoryName)` and `apply(ctx)` ([skills-host.js:20-23](./skills-host.js),
  [skills-host.js:40-69](./skills-host.js), [skills-host.js:88-107](./skills-host.js),
  [skills-host.js:114-153](./skills-host.js), [skills-host.js:162-173](./skills-host.js)).
- `parseSkillDocument` (exported by `skills-host.js` and re-exported by `index.js`) parses only the
  leading `---` frontmatter block: single-line `key: value` pairs, skipping blank lines and `#`
  comments, unquoting quoted values, and collecting folded (`>`, `>-`) or literal (`|`, `|-`) block
  scalars; an unsupported frontmatter line throws, a document without frontmatter returns an empty
  `meta` and the trimmed source as `body`, and the returned `body` is the text after the frontmatter,
  trimmed ([skills-host.js:27-28](./skills-host.js), [skills-host.js:40-69](./skills-host.js)).
- `reviewer-host.js` — exports `name = 'dsh-egm-reviewer'`,
  `inject = ['tools', 'subagents', 'agents']` and `apply(ctx)`; `apply` registers the `egm_reviewer`
  tool and the `agent/created` reviewer-isolation hook ([reviewer-host.js:16-18](./reviewer-host.js),
  [reviewer-host.js:65-120](./reviewer-host.js)).
- `egm_reviewer` tool (registered by `reviewer-host.js`) — inputs `{ description, prompt }` (both
  required strings; the prompt must name the `Persona:` file and every input path, which the child reads
  itself, because it sees none of the calling conversation) and output `{ kind: 'activation', subagentId }`; a call
  starts one `spawn` child in the `egm-reviewer` preset with `maxDepth: 1`, and the tool description
  forbids `subagent_fork` for reviews ([reviewer-host.js:22-47](./reviewer-host.js),
  [reviewer-host.js:77-90](./reviewer-host.js), [reviewer-host.js:103-116](./reviewer-host.js)).
- `reviewer-tools.js` — exports `name`, `inject`, `ALLOWED_TOOLS` (12 read/search allowlist
  patterns), `isAllowed(name)`, `hideNonReviewerTools(tools)` and `apply(ctx)`, which is mounted
  inside the `egm-reviewer` preset ([reviewer-tools.js:13-15](./reviewer-tools.js),
  [reviewer-tools.js:18-31](./reviewer-tools.js), [reviewer-tools.js:38-53](./reviewer-tools.js),
  [reviewer-tools.js:59-63](./reviewer-tools.js)).
- `cordis.patch.yml` — the bundle patch: host rows `egm` (`dsh-egm/skills-host`) and
  `egm-reviewer-tool` (`dsh-egm/reviewer-host`), plus the `egm-reviewer` preset composed from a
  persona, read-only file tools, file search, compaction and `dsh-egm/reviewer-tools`
  ([cordis.patch.yml:3-9](./cordis.patch.yml), [cordis.patch.yml:10-53](./cordis.patch.yml)).
- `package.json` — package manifest: the `exports` map exposes `.` (`index.js`), `./skills-host`,
  `./reviewer-host`, `./reviewer-tools`, `./locale/*.json`, `./icon` (`icon.svg`) and
  `./package.json`, and `dsh.bundle.patch` declares `cordis.patch.yml` as the bundle patch
  ([package.json:11-19](./package.json), [package.json:75-79](./package.json)).

**Invariants.**

- A skill directory under `skills/` is loaded only when its `SKILL.md` frontmatter has a kebab-case
  `name` equal to the directory name and a non-empty `description`, and its body is non-empty;
  anything else throws at activation so a packaging regression fails the plugin row instead of
  silently shrinking the install ([skills-host.js:114-153](./skills-host.js)).
- Each registered skill's `content` is the `<dsh_integration>` preamble followed by the verbatim
  upstream body, and its `resourceBase` is the package root
  ([skills-host.js:88-107](./skills-host.js), [skills-host.js:139-147](./skills-host.js)). The
  vendored files on disk are never rewritten.
- `egm_reviewer` fails closed unless the agent-presets service, a `spawn` provider and the declared
  `egm-reviewer` preset are all present, and it requires a non-empty prompt
  ([reviewer-host.js:49-58](./reviewer-host.js), [reviewer-host.js:91-102](./reviewer-host.js)).
- Every reviewer activation is a fresh `spawn` child in the `egm-reviewer` preset with
  `maxDepth: 1` and `delivery: 'parent'`; `subagent_fork` is never used
  ([reviewer-host.js:103-116](./reviewer-host.js)).
- The reviewer scope hides non-read tools available at setup; late or scope-local tools can
  remain visible. Preset and agent guards deny non-allowlisted calls; setup errors abort creation
  ([reviewer-host.js:66-75](./reviewer-host.js), [reviewer-tools.js:50-63](./reviewer-tools.js)).

**Side effects of the root modules.**

- Plugin activation reads every bundled `SKILL.md`, lists the `skills/` directory, registers the
  seven skills through `ctx.effect`, and logs the registration count
  ([skills-host.js:114-118](./skills-host.js), [skills-host.js:162-173](./skills-host.js)).
- The host registers the `egm_reviewer` tool and a reviewer-scope tool restriction; a tool call
  starts one child agent activation ([reviewer-host.js:77-120](./reviewer-host.js)).
- The adapter modules only read files (they import `readFileSync`/`readdirSync` and call no
  filesystem write API) ([skills-host.js:16-18](./skills-host.js)).

## Global Invariants

- **Vendored parity.** The 26 adapted upstream files are byte-identical to
  `google/elephant-goldfish-model` at the pinned commit, and their SHA-256 values are recorded in
  [upstream.lock.json](./upstream.lock.json); `test/upstream-lock.test.js` fails the package if a
  shipped file or vendored fixture drifts ([ADAPTATIONS.md](./ADAPTATIONS.md),
  [scripts/EGM.md](./scripts/EGM.md)).
- **No harness fork.** Harness mechanics are supplied only by the injected `<dsh_integration>`
  preamble; the vendored skills, personas and resources stay verbatim so one EGM skill set serves
  every harness ([ADAPTATIONS.md](./ADAPTATIONS.md), [skills-host.js:88-107](./skills-host.js)).
- **Goldfish isolation.** A Goldfish review must be a fresh, read-only child started with
  `egm_reviewer`; neither `subagent` nor `subagent_fork` may run a review, and reviewers cannot
  write, run commands, ask the user, read the session or delegate
  ([reviewer-host.js:103-116](./reviewer-host.js), [ADAPTER-NOTES.md](./ADAPTER-NOTES.md)).
- **Packing contract.** `package.json` `files` is the single packing contract;
  `test/manifest.test.js` asserts that every runtime file is covered and that every listed entry
  exists, and `test/`, `examples/` and `.github/` must never leak into the published tarball
  ([package.json:20-44](./package.json), [ci.yml:38-121](./.github/workflows/ci.yml)).
- **Human-controlled upstream pin.** `scripts/check-upstream.mjs` reports drift (exit 0 clean,
  1 drift, 2 error) but never re-adapts content or moves the pin silently; `--update-lock` is a
  human step ([scripts/EGM.md](./scripts/EGM.md)).
- **Plain ESM, no build.** The bundle ships plain JavaScript (`"type": "module"`, Node >= 22, an
  `engines.dsh` range) and needs no install-time build ([package.json:5-10](./package.json),
  [package.json:71-74](./package.json)).

## Global Side Effects

- **Harness composition.** Activating the plugin mutates Harness registries: seven skills, the
  `egm_reviewer` tool, the reviewer tool guard, and the `egm-reviewer` preset rows declared by the
  bundle patch ([skills-host.js:162-173](./skills-host.js),
  [reviewer-host.js:65-120](./reviewer-host.js), [cordis.patch.yml](./cordis.patch.yml)).
- **Child-agent work.** Each `egm_reviewer` call spends a fresh child agent in the read-only
  reviewer preset ([reviewer-host.js:103-116](./reviewer-host.js)).
- **Network, disk and subprocess (tooling only).** The CLI in `scripts/` can call
  `raw.githubusercontent.com` and the GitHub API, rewrites `upstream.lock.json` only under
  `--update-lock`, and reads git HEAD for `--update-lock --source`
  ([scripts/EGM.md](./scripts/EGM.md)).
- **CI automation.** [.github/workflows/ci.yml](./.github/workflows/ci.yml) runs `node --test` on
  Ubuntu with Node 22 and 24 and on Windows with Node 24, then asserts the packed file list.
  A separate Linux Node 24/Python 3.12 job runs both keyless native replay integration cases;
  [.github/workflows/upstream-sync.yml](./.github/workflows/upstream-sync.yml) runs the drift check
  daily (06:00 UTC), opens or refreshes the upstream-tracking issue on drift, and opens or refreshes
  a separate "Upstream sync check failed" issue when the check itself errors
  ([ci.yml:13-37](./.github/workflows/ci.yml), [upstream-sync.yml:16-185](./.github/workflows/upstream-sync.yml)).
- **Published files.** The npm tarball ships the vendored `skills/`, `agents/`, `resources/` and
  `locale/` trees, the adapter modules, the bundle patch, `scripts/check-upstream.mjs`, the human
  documentation and this blueprint; `test/`, `tests/`, `docs/testing/`, `examples/` and `.github/` stay
  repository-only ([package.json:20-44](./package.json), [ci.yml:38-121](./.github/workflows/ci.yml)).
